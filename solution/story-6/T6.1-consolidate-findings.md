## 1a. Architectural Findings (Cross-Cutting)

Beyond the per-story efficiency wins, two **system-level** findings affect how the optimisations should be sequenced:

| Finding | Detail | Decision home |
|---------|--------|---------------|
| **Dual orchestration / unowned container lifecycle** | Container lifecycle is owned by Drone in CI and Maven locally, selected by repo-local `skip.*` flags; logic is duplicated and has diverged (6 vs 7 aggregators, two `CORE_TAG` paths). Local ≠ CI runtime. | T6.2 §5 (a, f–j); migration in T5.3 §8 |
| **Build/publish integrity gap (build-once-promote)** | The integration-tested + Trivy-scanned image is rebuilt separately in the publish stage, so the shipped artifact is not the tested one. | T6.2 §5 (b), B9; Story 3 SUMMARY |

> These are not blockers for the local-first work, but they should be agreed before central rollout so optimisations land on a single, well-owned orchestration model. The **recommended options** (single owner via `mvn verify`; build-once-promote) are **not locked decisions** — the target and the decision sequence are defined in T1.2 "Target End State" and "Decision Order", with the register in T6.2 §5.

## 4. Security Improvements

| Improvement | Before | After |
|-------------|--------|-------|
| Runtime image | Full JDK (compiler, dev tools) | JRE only (minimal attack surface) |
| Debug port | Open by default (port 8077) | Disabled by default (opt-in via JAVA_OPTS) |
| JMX authentication | Explicitly disabled in CMD | Removed from default; opt-in per environment |
| Image size | ~550MB (more code = more vulnerabilities) | ~180MB (fewer packages to patch) |
| Build determinism | `yum update` (non-reproducible) | Pinned Alpine packages |
| HEALTHCHECK | Missing | Added (faster failure detection) |
