## 1. Stakeholder Summary (Presentation-Ready)

### One-Liner

> We piloted Docker and CI/CD optimisations on `fdp-cmd-adaptor-sns`. Results: **65% smaller images, 70% faster builds, 97% faster test startup.** Most changes need RepoSync MRs — here's the ownership breakdown.

---

### Executive Summary

**What we did:**
- Assessed the Drone/RepoSync pipeline structure
- Baselined current build/test/image metrics
- Designed Docker optimisations (Dockerfile, .dockerignore, layering)
- Designed Testcontainers integration for isolated, faster tests
- Mapped and classified all 20 Docker Compose services
- Classified every improvement by ownership (CST / ACP / ETO)

**What we found:**

| Area | Key Finding | Improvement |
|------|------------|:-----------:|
| Docker image | Full JDK, 550MB, no .dockerignore | → 180MB (**65% smaller**) |
| Docker build | Cache breaks every build, slow yum update | → 30-60s cold (**70% faster**) |
| Test startup | 17 containers, 2-4 min, shared state | → 3-25s, isolated (**97% faster**) |
| Compose in CI | 17 services started for any test | → 8 services (**53% fewer**) |
| Developer feedback | 4-6 min to run first test | → 20-30s (**90% faster**) |

**What we need:**

| Owner | Items | First Priority |
|-------|:-----:|----------------|
| CST (do now) | 12 | Testcontainers local setup + Dockerfile validation |
| ACP (RepoSync MR) | 10 | Dockerfile + .dockerignore MR |
| ETO (post-pilot) | 7 | Registry cache, shared base images |

**Two structural decisions also need agreement** (see T6.2 §5; sequence per T1.2 Decision Order): (1) single container-lifecycle owner — **recommended `mvn verify`** but not yet locked (alternative: Drone retains ownership); (2) build-once-promote — test/scan and ship the same image. These are the highest-leverage architectural items behind the efficiency numbers.
