## 4. Re-Measurement Method

### CI Pipeline

1. Open Drone UI for `fdp-cmd-adaptor-sns`.
2. Filter to `develop` branch and successful runs.
3. Capture the last 5-10 successful runs.
4. Record total duration and per-step duration for each run.
5. Separately count failed/cancelled runs in the same sample window.
6. Calculate average, median, fastest, slowest and most expensive step.
7. Repeat the same process after the optimisation story is implemented.

### Docker Build and Image

Run from the repository root after a Maven package/install has produced the app JAR:

```bash
du -sh cmd-adaptor-sns/
docker builder prune -af
time docker build -t cmd-adaptor-sns:baseline -f cmd-adaptor-sns/Dockerfile cmd-adaptor-sns/
time docker build -t cmd-adaptor-sns:baseline -f cmd-adaptor-sns/Dockerfile cmd-adaptor-sns/
docker images cmd-adaptor-sns:baseline
docker history cmd-adaptor-sns:baseline
```

For the after measurement, use the same machine, Docker version and build command where possible.

### Integration Tests

1. Capture Drone timings for infrastructure startup, aggregators, command-adaptor startup and integration-test execution.
2. Capture Maven/Failsafe duration from the integration-test logs.
3. Record any wait-check timeout, Kafka/Redis readiness issue or test-order failure.
4. Repeat after Testcontainers or Compose rationalisation changes.
5. Compare startup/wait time separately from actual test execution time.
