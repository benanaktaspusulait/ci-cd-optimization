## 1. Current Dockerfile Analysis

### Base Image

| Property | Value |

| Type | Full JDK (not JRE) |
| Estimated size | ~450-480 MB |
| OS | Amazon Linux 2 |

### Current Build Approach

The Dockerfile does **not** build the application — it only packages a pre-built JAR:

```dockerfile
FROM amazoncorretto:17

COPY ./target/cmd-adaptor-sns-exec.jar /local
COPY ./target/dependencies/opentelemetry-javaagent.jar /local/opentelemetry-javaagent.jar

RUN yum install -y shadow-utils unzip \
    && yum update -y [many packages] \
    && yum erase -y vim-data \
    && yum clean all \
    && curl ... envconsul ... \
    && adduser fdpuser \
    && chmod/chown ...

USER fdpuser
CMD ["java", "-javaagent:...", "-jar", "/local/cmd-adaptor-sns-exec.jar"]
```

**Flow:** Maven builds the JAR externally (CI step 7) → Dockerfile copies JAR + OTel agent → installs system deps → creates user → runs.

| Layer | Content | Estimated Size |
|-------|---------|---------------|

| `COPY` JARs | Application JAR + OTel agent | ~50-80 MB |
| `RUN` yum + envconsul + user | System packages + envconsul binary | ~30-50 MB |
| **Total image** | | **~530-610 MB** |

## 2. Current Build Context

### Build Context Path

The Docker build context is `cmd-adaptor-sns/`:
- **In CI (compose build):** docker-compose.yml specifies `build: ../../../../../cmd-adaptor-sns` for the `command-adaptor` service
- **In Artifactory pipeline:** `.drone.star` explicitly sets `'context': 'cmd-adaptor-sns'` and `'dockerfile': 'cmd-adaptor-sns/Dockerfile'`

### .dockerignore Status

**Does not exist.** There is no `.dockerignore` file anywhere in the repository.

This means the entire `cmd-adaptor-sns/` directory is sent as build context, including:
- `src/` (all Java source code — not needed, JAR is pre-built)
- `target/` (build output — only the exec JAR and OTel agent are needed)
- `pom.xml` (not needed in build)
- Any IDE files, logs, etc.

### Estimated Build Context Size

| Directory | Estimated Size | Needed in Docker build? |
|-----------|---------------|:-----------------------:|
| `target/` (full) | ~100-150 MB | Only 2 files (~50-80 MB) |
| `src/` | ~5-10 MB | ❌ |
| `pom.xml` | <1 KB | ❌ |
| Other files | ~1-5 MB | ❌ |
| **Total context sent** | **~110-170 MB** | |
| **Actually needed** | **~50-80 MB** | (2 JAR files only) |

**Waste: ~60-90 MB of unnecessary context per build.**

## 4. Image Size Baseline

| Metric | Estimated Value | Target (pilot) |
|--------|-----------------|----------------|
| Final image size | ~530-610 MB | ≤ 370 MB (≥ 30% reduction) |
| Base image size | ~450-480 MB | — |
| Application layer | ~50-80 MB | — |
| System deps layer | ~30-50 MB | — |

### Why the Image is Large

1. **Full JDK** — `amazoncorretto:17` includes compiler, dev tools, not needed at runtime
2. **yum update** — pulls updated packages into a new layer
3. **Amazon Linux 2** — heavier than Alpine/distroless
4. **envconsul binary** — 15MB+ added for Vault integration
5. **No multi-stage** — everything in one image
