### How to Re-measure

1. Open Drone UI for `fdp-cmd-adaptor-sns`
2. Filter by branch: `develop`, status: `success`
3. Select last 10 runs
4. For each run: record total duration + per-step durations
5. Calculate average, median, fastest and slowest successful run where possible
6. Record in metrics template
7. Review the last 20 `develop` runs separately for failed/cancelled run counts and common failure categories

## 6. Observations

### Duplicate Maven Build

The `mvn clean install` runs **twice** per develop push:
1. CI pipeline step 7 (full build + unit tests)
2. ARTIFACTORY pipeline step 5 (full build + `dependency:go-offline`)

This means ~3-5 min of Maven build time is duplicated. The Artifactory pipeline could potentially reuse artifacts from CI if a workspace/cache were shared.

This should be investigated later as a possible build-once/promote-once improvement; it is not part of the baseline capture task.

### Sequential Execution Model

The CI pipeline cannot fully parallelise because:
- Integration tests need infra (Kafka, Redis) AND aggregators AND the command adaptor
- These have sequential dependencies: infra → aggregators → adaptor → tests
- No way to pre-cache or pre-pull images between runs (ephemeral DIND)

### No Pipeline Caching

- No repo-visible Maven dependency cache between Drone runs was identified. Dependency resolution may still benefit from Artifactory/proxy caching outside this pipeline.
- No repo-visible Docker layer cache between runs was identified because DIND is ephemeral. Any platform-level caching would need confirmation.
- Every run appears to resolve dependencies and rebuild Docker layers within the pipeline context unless external caching is confirmed.

### DVLA Portability Signal

The DVLA source excerpts show the same high-cost pipeline pattern: RepoSync-managed Drone pipeline, DIND, docker-compose orchestration, full Maven build, command-adaptor image build, integration-test container, Trivy scan and Artifactory publish. This supports using SNS as the working pilot while treating DVLA as evidence that the baseline findings are likely portable across the FDP adaptor family.
