## Outcome

The pilot repository defines 20 Compose services. Repository inspection shows that 17 are started in the current CI path, while three are not directly used there. This is structural evidence about configuration and invocation; it is not proof that any service can be removed safely or that CI would become faster.

## Topology observations

- Infrastructure chain: Zookeeper → Kafka → Schema Registry, with Redis and LocalStack supporting parts of the test topology.
- Six aggregators, the command adaptor and test utilities form the current CI/full-E2E application path.
- Kafdrop is brought into CI through a Compose dependency chain rather than a demonstrated functional test requirement.
- Drone and the Maven `docker-compose-maven-plugin` encode separate orchestration paths. Story 1 evidence records topology differences between them.
- The Compose file is RepoSync-controlled. A local or temporary target-repository experiment would not establish the durable adoption route.

## Scope boundaries

- Redis-only functional evidence must not be extrapolated to Kafka/Schema Registry or the full E2E topology.
