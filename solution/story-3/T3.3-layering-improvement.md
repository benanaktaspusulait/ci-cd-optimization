## 1. Selected First Candidate

The safest first candidate is a layer-order prototype that preserves the current packaging lifecycle:

```text
Maven build produces target artefacts -> Dockerfile packages the JAR and OpenTelemetry agent
```

The prototype should move expensive, rarely changing setup before application artefact copies:

1. keep the current runtime base initially;
2. run package/envconsul/user setup before copying the JAR;
3. copy the OpenTelemetry agent and application JAR late;
4. keep post-copy ownership/permission work small;
5. measure before/after before recommending anything for RepoSync.

This avoids the larger risk of changing Java distribution, operating-system family, Maven build lifecycle and runtime entrypoint in one step.

## 2. Candidate Dockerfile Shape

This is a local prototype shape, not a committed production Dockerfile:

```dockerfile
FROM amazoncorretto:17

WORKDIR /tmp

# Expensive setup first. This layer changes rarely and can be reused in local/same-daemon cached builds.
RUN yum install -y shadow-utils unzip \
    && yum update -y ca-certificates cpio curl cyrus-sasl-lib expat glib2 \
       libcurl libdb libssh2 libdb-utils libnghttp2 libpng libtasn1 libxml2 \
       ncurses ncurses-base ncurses-libs nss nss-util nss-softokn nspr \
       openldap openssl-libs python python-libs sqlite xz-libs yum zlib \
    && yum erase -y vim-data \
    && yum clean all \
    && rm -rf /var/cache/yum \
    && curl --silent --output /tmp/envconsul.zip \
       https://releases.hashicorp.com/envconsul/0.13.1/envconsul_0.13.1_linux_amd64.zip \
    && unzip envconsul.zip \
    && rm -f envconsul.zip \
    && mv envconsul /usr/local/bin/envconsul \
    && chown root:root /usr/local/bin/envconsul \
    && chmod 0755 /usr/local/bin/envconsul \
    && adduser -u 1000 -U -m -s /bin/bash fdpuser

# Frequently changing runtime artefacts last.
COPY ./target/dependencies/opentelemetry-javaagent.jar /local/opentelemetry-javaagent.jar
COPY ./target/cmd-adaptor-sns-exec.jar /local/cmd-adaptor-sns-exec.jar

RUN chmod 0755 /local/cmd-adaptor-sns-exec.jar \
    && chown fdpuser:fdpuser /local/cmd-adaptor-sns-exec.jar \
    && chmod 0755 /local/opentelemetry-javaagent.jar \
    && chown fdpuser:fdpuser /local/opentelemetry-javaagent.jar

WORKDIR /home/fdpuser
USER fdpuser

CMD ["java", "-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:8077",
     "-javaagent:/local/opentelemetry-javaagent.jar",
     "-Dcom.sun.management.jmxremote", "-Dcom.sun.management.jmxremote.port=9012",
     "-Dcom.sun.management.jmxremote.rmi.port=9012",
     "-Dcom.sun.management.jmxremote.authenticate=false",
     "-Dcom.sun.management.jmxremote.local.only=false",
     "-Dcom.sun.management.jmxremote.ssl=false",
     "-Djava.rmi.server.hostname=localhost",
     "-jar", "/local/cmd-adaptor-sns-exec.jar"]
```

This intentionally avoids changing base image, healthcheck, entrypoint, debug/JMX defaults or Maven build lifecycle in the first measurement. Those can be separate follow-up candidates.

## 3. Why This Candidate First

| Reason | Detail |
|--------|--------|
| Low functional risk | Same base image, same package list, same envconsul version, same user, same command |
| Clear attribution | The main change is layer order, so before/after cache behaviour is easier to explain |
| Compatible with current pipeline | Maven artefacts are still produced outside Docker |
| RepoSync-ready | The change can be proposed centrally if the local prototype is positive |
| Honest CI expectation | Helps local/same-daemon cache reuse; does not promise a cold CI reduction without measurement |

---

## 4. Deferred Candidates

| Candidate | Why deferred |
|----------|--------------|
| Smaller Java runtime base | Requires approved image-source / Artifactory path, runtime compatibility checks and likely security review |
| Alpine/musl base | Potential native library, certificate, tooling and agent compatibility risk |
| BuildKit cache mounts | Local prototype possible, but Drone/DIND support is unproven until smoke validation |
| Maven multi-stage Dockerfile | Changes the current build lifecycle and duplicates work already done by Maven in CI |
| Debug/JMX default changes | Security/operability work, but should be tested separately from build optimisation |
| HEALTHCHECK | Useful only after application health port/path is confirmed |

## 5. Verification Plan

Run after the required Maven artefacts exist:

```bash
# Current Dockerfile baseline, using T2.3 values unless remeasured.
time docker build --no-cache -t cmd-adaptor-sns:before \
  -f cmd-adaptor-sns/Dockerfile cmd-adaptor-sns/
docker images cmd-adaptor-sns:before
docker history --no-trunc cmd-adaptor-sns:before

# Candidate layer-order prototype.
time docker build --no-cache -t cmd-adaptor-sns:layer-order-candidate \
  -f cmd-adaptor-sns/Dockerfile.layer-order-prototype cmd-adaptor-sns/
docker images cmd-adaptor-sns:layer-order-candidate
docker history --no-trunc cmd-adaptor-sns:layer-order-candidate

# Smoke checks.
docker run --rm --entrypoint sh cmd-adaptor-sns:layer-order-candidate -c \
  'java -version && envconsul --version && test -f /local/cmd-adaptor-sns-exec.jar && test -f /local/opentelemetry-javaagent.jar'
```

Warm-cache check:

```bash
touch cmd-adaptor-sns/target/cmd-adaptor-sns-exec.jar
time docker build -t cmd-adaptor-sns:layer-order-candidate \
  -f cmd-adaptor-sns/Dockerfile.layer-order-prototype cmd-adaptor-sns/
```

Capture Trivy if the candidate image is built in the local environment:

```bash
trivy image --severity CRITICAL,HIGH --exit-code 0 cmd-adaptor-sns:layer-order-candidate
```
