## 1. Goal

Validate whether Dockerfile layer reordering improves same-daemon warm-cache rebuild behaviour after application artefact changes, without changing base image, package list, `envconsul` version, Maven lifecycle, `CMD`, debug/JMX settings, healthcheck, entrypoint or runtime behaviour.

T3.3 is not primarily a cold-build optimisation task. On a no-cache build, the `yum`/install/`envconsul` layer still runs and is expected to remain dominant. The main measurement question is:

```text
If only the application JAR changes, can Docker reuse the expensive yum/envconsul/user setup layer?
```

The intended target claim is limited to:

```text
Layer ordering may improve same-daemon warm-cache rebuild behaviour after application artefact changes.
```

Do not claim a general Docker build improvement, CI saving, image-size reduction or production Dockerfile recommendation from T3.3 before measurement and ownership confirmation.

## 3. Selected Candidate

The selected T3.3 candidate is a layer-order prototype that preserves the current packaging lifecycle:

```text
Maven build produces target artefacts -> Dockerfile packages the JAR and OpenTelemetry agent
```

The prototype should move expensive, rarely changing setup before application artefact copies:

1. keep the current runtime base image;
2. run package/`envconsul`/user setup before copying the JAR;
3. copy the OpenTelemetry agent and application JAR late;
4. keep post-copy ownership/permission work small and limited to copied artefacts;
5. measure current vs prototype warm-cache rebuild behaviour before recommending anything for RepoSync.

This avoids changing Java distribution, operating-system family, Maven build lifecycle, runtime entrypoint, debug/JMX defaults or base-image source in the same task.

## 4. Prototype Dockerfile Shape

Create the prototype separately from the production Dockerfile:

```text
cmd-adaptor-sns/Dockerfile.layer-order-prototype
```

This is a local prototype shape, not a committed production Dockerfile replacement:

```dockerfile
FROM amazoncorretto:17

WORKDIR /tmp

# Expensive setup first. This layer changes rarely and can be reused in local/same-daemon cached builds.
RUN yum install -y shadow-utils unzip \
    && yum update -y ca-certificates cpio curl cyrus-sasl-lib expat glib2 \
       libcurl libdb libssh2 libdb-utils libnghttp2 libpng libtasn1 libxml2 \
       ncurses ncurses-base ncurses-libs nss nss-util nss-softokn nspr \
       openldap openssl-libs python python-libs sqlite xz-libs yum zlib \
    && yum erase -y vim-data \
    && yum clean all \
    && rm -rf /var/cache/yum \
    && curl --silent --output /tmp/envconsul.zip \
       https://releases.hashicorp.com/envconsul/0.13.1/envconsul_0.13.1_linux_amd64.zip \
    && unzip envconsul.zip \
    && rm -f envconsul.zip \
    && mv envconsul /usr/local/bin/envconsul \
    && chown root:root /usr/local/bin/envconsul \
    && chmod 0755 /usr/local/bin/envconsul \
    && adduser -u 1000 -U -m -s /bin/bash fdpuser

# Frequently changing runtime artefacts last.
COPY ./target/cmd-adaptor-sns-exec.jar /local/cmd-adaptor-sns-exec.jar
COPY ./target/dependencies/opentelemetry-javaagent.jar /local/opentelemetry-javaagent.jar

RUN chmod 0755 /local/cmd-adaptor-sns-exec.jar \
    && chown fdpuser:fdpuser /local/cmd-adaptor-sns-exec.jar \
    && chmod 0755 /local/opentelemetry-javaagent.jar \
    && chown fdpuser:fdpuser /local/opentelemetry-javaagent.jar

WORKDIR /home/fdpuser
USER fdpuser

CMD ["java", "-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:8077", \
     "-javaagent:/local/opentelemetry-javaagent.jar", \
     "-Dcom.sun.management.jmxremote", "-Dcom.sun.management.jmxremote.port=9012", \
     "-Dcom.sun.management.jmxremote.rmi.port=9012", \
     "-Dcom.sun.management.jmxremote.authenticate=false", \
     "-Dcom.sun.management.jmxremote.local.only=false", \
     "-Dcom.sun.management.jmxremote.ssl=false", \
     "-Djava.rmi.server.hostname=localhost", \
     "-jar", "/local/cmd-adaptor-sns-exec.jar"]
```

This intentionally avoids changing base image, package list, `envconsul` version, healthcheck, entrypoint, debug/JMX defaults, runtime command or Maven build lifecycle.
