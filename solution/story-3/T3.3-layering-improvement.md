## 1. Selected Improvement: Multi-Stage + Layer Reordering + JRE Base

Based on T3.1 analysis, combining the top-3 opportunities into one coherent Dockerfile:

1. **Switch to JRE-only Alpine base** (biggest size win)
2. **Reorder: system deps before application JARs** (cache win)
3. **Split monolithic RUN into logical layers** (better cache granularity)

---

## 2. Proposed Dockerfile

```dockerfile
# ============================================================
# cmd-adaptor-sns — Optimised Dockerfile
# ============================================================
# Changes from current:
#   1. Base: amazoncorretto:17 (full JDK) → eclipse-temurin:17-jre-alpine (JRE only)
#   2. Layer order: system deps FIRST (cached), app JARs LAST (change often)
#   3. Monolithic RUN split into logical steps
#   4. envconsul install separated (cached independently)
#   5. HEALTHCHECK added
#   6. Debug/JMX moved to optional ENV (not hardcoded in CMD)
# ============================================================

FROM eclipse-temurin:17-jre-alpine

# --- Layer 1: System dependencies (changes rarely → cached) ---
RUN apk add --no-cache \
        ca-certificates \
        curl \
        unzip \
    && update-ca-certificates

# --- Layer 2: envconsul binary (changes only on version bump → cached) ---
ARG ENVCONSUL_VERSION=0.13.1
RUN curl --silent --output /tmp/envconsul.zip \
        "https://releases.hashicorp.com/envconsul/${ENVCONSUL_VERSION}/envconsul_${ENVCONSUL_VERSION}_linux_amd64.zip" \
    && unzip /tmp/envconsul.zip -d /usr/local/bin/ \
    && rm -f /tmp/envconsul.zip \
    && chmod 0755 /usr/local/bin/envconsul

# --- Layer 3: Non-root user (changes never → cached) ---
RUN adduser -D -u 1000 fdpuser

# --- Layer 4: Application JARs (changes every build → last layer) ---
COPY --chown=fdpuser:fdpuser ./target/dependencies/opentelemetry-javaagent.jar /local/opentelemetry-javaagent.jar
COPY --chown=fdpuser:fdpuser ./target/cmd-adaptor-sns-exec.jar /local/cmd-adaptor-sns-exec.jar

# --- Runtime setup ---
WORKDIR /home/fdpuser
USER fdpuser

HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
    CMD wget --quiet --tries=1 --spider http://localhost:7112/actuator/health || exit 1

# Default: no debug agent, no JMX remote
# Override via JAVA_OPTS environment variable for debug/monitoring
ENV JAVA_OPTS=""

ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -javaagent:/local/opentelemetry-javaagent.jar -jar /local/cmd-adaptor-sns-exec.jar"]
```

## 3. Changes Explained

### 3.1 Base Image: `amazoncorretto:17` → `eclipse-temurin:17-jre-alpine`

| Property | Before | After |
|----------|--------|-------|
| Image | `amazoncorretto:17` | `eclipse-temurin:17-jre-alpine` |
| Type | Full JDK (compiler, tools) | JRE only (runtime) |
| OS | Amazon Linux 2 (glibc) | Alpine Linux (musl) |
| Size | ~450 MB | ~120 MB |
| Package manager | yum | apk |
| Security surface | Large (JDK tools, dev libs) | Minimal (JRE only) |

**Why Eclipse Temurin?**
- Adoptium (formerly AdoptOpenJDK) — well-maintained, widely used
- Alpine variant is smallest
- JRE-only removes attack surface (no compiler)
- Compatible with Spring Boot 3.x + Java 17

**Alternative if musl compatibility is a concern:** `eclipse-temurin:17-jre-jammy` (Ubuntu-based, ~200MB, glibc)

### 3.2 Layer Reordering

**Before (cache breaks every build):**
```
FROM base
COPY app.jar           ← changes every build
RUN install deps       ← REBUILT every time (after COPY)
```

**After (system deps cached):**
```
FROM base
RUN install deps       ← cached (changes rarely)
RUN install envconsul  ← cached (changes on version bump)
RUN adduser            ← cached (never changes)
COPY app.jar           ← last layer (changes every build — only this rebuilds)
```

### 3.3 Split Monolithic RUN

**Before:** One massive RUN (yum install + yum update + curl + unzip + adduser + chmod)
**After:** Three logical layers:
1. System packages (`apk add`)
2. envconsul binary (with version ARG)
3. User creation

If envconsul version doesn't change, only the COPY layer rebuilds on code changes.

### 3.4 Debug/JMX as Environment Variable

**Before:** Debug agent and JMX hardcoded in CMD:
```dockerfile
CMD ["java", "-agentlib:jdwp=...", "-Dcom.sun.management.jmxremote...", "-jar", "..."]
```

**After:** Clean default, override via `JAVA_OPTS`:
```dockerfile
ENV JAVA_OPTS=""
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -javaagent:... -jar ..."]
```

Enable debug in dev:
```yaml
# docker-compose.yml or Helm values
environment:
  JAVA_OPTS: "-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:8077 -Dcom.sun.management.jmxremote..."
```

### 3.5 HEALTHCHECK Added

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
    CMD wget --quiet --tries=1 --spider http://localhost:7112/actuator/health || exit 1
```

> **Note:** Port 7112 is the command-adaptor application port (from docker-compose.yml). Confirm the health endpoint path and port with the application's Spring Boot config (`application.yml`). Port 8077 is the JDWP debug port — NOT the health endpoint.

## 4. Expected Impact

| Metric | Before | After | Improvement |
|--------|--------|-------|:-----------:|
| Final image size | ~550 MB | ~180-200 MB | **~65% reduction** |
| Build time (cold, no cache) | ~2-3 min | ~30-60s | **~70% reduction** |
| Build time (warm, code change only) | ~1.5-2 min | ~5-10s | **~90% reduction** |
| Cache invalidation on code change | Entire RUN layer rebuilds (~60-120s) | Only COPY layer rebuilds (~2s) | Significant |
| Security surface | Full JDK + yum packages | JRE only + minimal Alpine | Reduced |
| Build context (with .dockerignore) | ~150 MB | ~80 MB | ~50% |

## 5. Compatibility Considerations

| Concern | Risk | Mitigation |
|---------|------|-----------|
| Alpine musl vs glibc | Low — Spring Boot / Java 17 works fine on Alpine | Use `-jre-jammy` (Ubuntu) if native libs needed |
| Missing `shadow-utils` (adduser) | None — Alpine has `adduser` built-in | Different syntax (`adduser -D` vs `adduser -U -m`) |
| envconsul on Alpine | Low — static binary, works on both | Verify binary runs: `docker run --rm image envconsul --version` |
| `yum update` security patches removed | Low — Alpine base is regularly patched upstream | Use pinned tag + scheduled rebuild |
| HEALTHCHECK port | Medium — need to confirm actual health endpoint | Check `application.yml` for management port; docker-compose.yml shows command-adaptor exposes 7112 |
| JAVA_OPTS entrypoint | Medium — existing deployments may not set JAVA_OPTS | Default is empty (clean startup); Helm values must add debug opts for dev |

## 6. Verification Steps

```bash
# 1. Build the optimised image
docker build -t cmd-adaptor-sns:optimised -f Dockerfile.optimised cmd-adaptor-sns/

# 2. Compare sizes
docker images | grep cmd-adaptor-sns

# 3. Verify app starts
docker run --rm -p 8077:8077 cmd-adaptor-sns:optimised
# Check: application startup logs appear, no ClassNotFoundException

# 4. Verify envconsul works
docker run --rm cmd-adaptor-sns:optimised envconsul --version

# 5. Verify non-root
docker run --rm cmd-adaptor-sns:optimised whoami
# Expected: fdpuser

# 6. Verify healthcheck
docker inspect cmd-adaptor-sns:optimised | jq '.[0].Config.Healthcheck'

# 7. Cache test: change jar, rebuild
touch cmd-adaptor-sns/target/cmd-adaptor-sns-exec.jar
time docker build -t cmd-adaptor-sns:optimised -f Dockerfile.optimised cmd-adaptor-sns/
# Expected: only COPY layer rebuilds (~2-5s)
```
