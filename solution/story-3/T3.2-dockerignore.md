## 1. Current State

**`.dockerignore` does not exist** in the repository. No file at:
- `cmd-adaptor-sns/.dockerignore` (build context root)
- Root-level `.dockerignore`

This means **all files** in `cmd-adaptor-sns/` are sent as Docker build context, including source code, test output, IDE files, and Maven build artifacts that aren't needed.

---

## 2. Build Context Analysis

The Docker build context is `cmd-adaptor-sns/` (from `docker-compose.yml` — the `command-adaptor` service has `build: ../../../../../cmd-adaptor-sns`). In CI, the build is triggered via `docker-compose up --build command-adaptor`.

### What the Dockerfile actually needs:

```dockerfile
COPY ./target/cmd-adaptor-sns-exec.jar /local
COPY ./target/dependencies/opentelemetry-javaagent.jar /local/opentelemetry-javaagent.jar
```

**Only 2 files are needed.** Everything else is waste.

---

## 3. Proposed .dockerignore

**File location:** `cmd-adaptor-sns/.dockerignore`

```gitignore
# Source code (not needed — JAR is pre-built)
src/

# Maven build output (except the 2 files we need)
target/**
!target/cmd-adaptor-sns-exec.jar
!target/dependencies/
!target/dependencies/opentelemetry-javaagent.jar

# Maven wrapper
.mvn/
mvnw
mvnw.cmd

# Build config
pom.xml

# IDE / editor
.idea/
.vscode/
*.iml
*.ipr
*.iws

# OS files
.DS_Store
Thumbs.db

# VCS
.git/
.gitignore

# Logs
*.log

# Temp
temp/
.tmp/
```

---

## 4. Alternative Approach (Simpler)

If the negation pattern (`!target/...`) causes issues, a simpler approach:

```gitignore
# Exclude everything
*

# Include only what Dockerfile needs
!target/cmd-adaptor-sns-exec.jar
!target/dependencies/
!target/dependencies/opentelemetry-javaagent.jar
!Dockerfile
```

This "deny all, allow specific" pattern guarantees only the required files enter the context.

---

## 5. Expected Impact

| Metric | Before | After | Reduction |
|--------|--------|-------|:---------:|
| Build context size | ~100-150 MB | ~55-80 MB | **~45-50%** |
| Files sent to daemon | Hundreds (src/, target/, etc.) | 3 (JAR + OTel agent + Dockerfile) | 99%+ |
| Cache invalidation risk | Any source file change invalidates | Only JAR/agent changes matter | Significant |
| Build context transfer time | ~2-5s | ~1-2s | ~50% |
