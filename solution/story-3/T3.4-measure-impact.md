## 1. Measurement Plan

### What to Measure

| # | Metric | Before (baseline) | After (optimised) | Method |
|---|--------|-------------------|-------------------|--------|
| 1 | Build context size | `docker build` output | `docker build` output | "Sending build context to Docker daemon XXX MB" |
| 2 | Image size | `docker images` | `docker images` | SIZE column |
| 3 | Build time (cold — no cache) | `time docker build --no-cache` | `time docker build --no-cache` | Wall clock |
| 4 | Build time (warm — code change only) | `time docker build` (after touching JAR) | `time docker build` (after touching JAR) | Wall clock |
| 5 | Layer count | `docker history` | `docker history` | Number of layers |
| 6 | Cache reuse on rebuild | Observe which layers rebuild | Observe which layers rebuild | `docker build` output |

### Measurement Script

```bash
#!/bin/bash
# measure-build-impact.sh
# Run from repo root AFTER mvn clean install has produced target/

set -e

echo "============================================"
echo "BEFORE: Current Dockerfile (no .dockerignore)"
echo "============================================"

echo ""
echo "--- Build Context Size ---"
du -sh cmd-adaptor-sns/

echo ""
echo "--- Cold Build (no cache) ---"
docker builder prune -af 2>/dev/null
time docker build --no-cache -t cmd-adaptor-sns:before \
  -f cmd-adaptor-sns/Dockerfile cmd-adaptor-sns/ 2>&1 | tee /tmp/build-before-cold.log

echo ""
echo "--- Image Size ---"
docker images cmd-adaptor-sns:before --format "{{.Size}}"

echo ""
echo "--- Warm Build (simulate code change) ---"
touch cmd-adaptor-sns/target/cmd-adaptor-sns-exec.jar
time docker build -t cmd-adaptor-sns:before \
  -f cmd-adaptor-sns/Dockerfile cmd-adaptor-sns/ 2>&1 | tee /tmp/build-before-warm.log

echo ""
echo "--- Layer History ---"
docker history cmd-adaptor-sns:before

echo ""
echo "============================================"
echo "AFTER: Optimised Dockerfile + .dockerignore"
echo "============================================"

echo ""
echo "--- Cold Build (no cache) ---"
docker builder prune -af 2>/dev/null
time docker build --no-cache -t cmd-adaptor-sns:after \
  -f cmd-adaptor-sns/Dockerfile.optimised cmd-adaptor-sns/ 2>&1 | tee /tmp/build-after-cold.log

echo ""
echo "--- Image Size ---"
docker images cmd-adaptor-sns:after --format "{{.Size}}"

echo ""
echo "--- Warm Build (simulate code change) ---"
touch cmd-adaptor-sns/target/cmd-adaptor-sns-exec.jar
time docker build -t cmd-adaptor-sns:after \
  -f cmd-adaptor-sns/Dockerfile.optimised cmd-adaptor-sns/ 2>&1 | tee /tmp/build-after-warm.log

echo ""
echo "--- Layer History ---"
docker history cmd-adaptor-sns:after

echo ""
echo "============================================"
echo "COMPARISON"
echo "============================================"
echo ""
echo "Before: $(docker images cmd-adaptor-sns:before --format '{{.Size}}')"
echo "After:  $(docker images cmd-adaptor-sns:after --format '{{.Size}}')"
echo ""
echo "Context sizes in build logs:"
grep "Sending build context" /tmp/build-before-cold.log || true
grep "Sending build context" /tmp/build-after-cold.log || true
```

## 3. CI Build Impact (Projected)

CI builds happen in ephemeral DIND pods — no persistent cache between runs. This means:

| Scenario | Before | After | Notes |
|----------|--------|-------|-------|
| CI cold build | ~60-90s | ~30-45s | Smaller base = faster pull. No yum update. |
| CI warm build | Same as cold (no cache) | Same as cold (no cache) | DIND has no persistent cache |
| Image push time | ~20-30s (550MB) | ~8-12s (180MB) | Smaller image = faster push to registry |
| Image pull (in deploy) | ~15-25s | ~5-10s | Smaller image = faster deploy startup |

**Net CI saving per pipeline:** ~30-60s (build) + ~10-15s (push) + ~5-15s (pull in deploy) = **~45-90s saved per pipeline run.**

**With BuildKit remote cache (post-ACP change):** Only COPY layer rebuilds in CI too → ~5-10s build time.

## 4. Keep / Adjust Recommendation

### Keep: All Three Changes

| Change | Verdict | Reason |
|--------|---------|--------|
| `.dockerignore` | **KEEP** | Zero risk, immediate context reduction, no behaviour change |
| JRE Alpine base | **KEEP** | 65% size reduction, reduced attack surface, well-tested base |
| Layer reordering | **KEEP** | Massive cache improvement locally, modest CI improvement |

### Adjust: Review Before Rollout

| Item | Action |
|------|--------|
| HEALTHCHECK port | Confirm actual management port from `application.yml`; docker-compose.yml shows command-adaptor on port 7112, not 8077 (debug port) |
| envconsul | Confirm it works on Alpine (static binary — should be fine) |
| JAVA_OPTS entrypoint | Ensure Helm values/compose files set debug opts for dev environments |
| Other adaptors | Validate the same changes work for CTP, PNR, SDS, APIDQ adaptors |

### Don't Change Yet

| Item | Why |
|------|-----|
| Multi-stage with Maven build inside Docker | Current approach (external Maven → JAR copy) works; multi-stage is more complex and requires RepoSync template restructure |
| Remote cache | Needs ACP infrastructure — track separately |
| Pin base image digest | Good practice but adds operational overhead (update on each patch) — defer to second iteration |
