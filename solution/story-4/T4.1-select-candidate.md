## 2. Selection: Redis

### Why Redis First

| Criterion | Redis | Kafka | LocalStack |
|-----------|:-----:|:-----:|:----------:|
| Setup complexity | ✅ Minimal (single container, no deps) | ⚠️ Needs ZK or KRaft | ✅ Minimal |
| Startup speed | ✅ ~2-3s | ⚠️ ~15-20s | ⚠️ ~10-15s |
| Test isolation benefit | ✅ High (shared cache state between tests) | ✅ High (shared topics) | ⚠️ Medium (IAM state less impactful) |
| Existing test usage | ✅ Aggregators + adaptor use Redis for caching | ✅ All services use Kafka | ⚠️ Only IAM mock |
| Testcontainers module | ✅ Simple GenericContainer | ✅ Official KafkaContainer | ✅ Official LocalStackContainer |
| Demonstrates value quickly | ✅ Quick win for team | ⚠️ More setup work | ⚠️ Less visible benefit |

### Redis Selection Rationale

1. **Fastest to implement** — single container, no dependencies on other services
2. **Highest test-isolation ROI** — shared Redis state is a common source of flaky tests
3. **Proves the pattern** — once Redis works, Kafka + Schema Registry follow the same approach
4. **Low risk** — if it fails, we haven't invested much time
5. **Team sees value fast** — reduces most common "but it worked on my machine" issue

## 5. Implementation Approach (Preview for T4.2)

```java
@Testcontainers
class RedisIntegrationTest {

    @Container
    static GenericContainer<?> redis = new GenericContainer<>("redis:5.0.6")
            .withExposedPorts(6379);

    @DynamicPropertySource
    static void redisProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.redis.host", redis::getHost);
        registry.add("spring.redis.port", () -> redis.getMappedPort(6379));
    }

    @Test
    void shouldCacheAndRetrieve() {
        // Test with isolated Redis — no shared state with other tests
    }
}
```

## 6. Second Candidate (After Redis)

Once Redis proves the pattern, the natural next step is **Kafka + Schema Registry**:

```java
@Container
static KafkaContainer kafka = new KafkaContainer(
    DockerImageName.parse("confluentinc/cp-kafka:7.5.5"));

@Container
static GenericContainer<?> schemaRegistry = new GenericContainer<>(
    DockerImageName.parse("confluentinc/cp-schema-registry:7.5.5"))
        .withExposedPorts(8081)
        .withEnv("SCHEMA_REGISTRY_KAFKASTORE_BOOTSTRAP_SERVERS", 
                 "PLAINTEXT://" + kafka.getNetworkAliases().get(0) + ":9092")
        .dependsOn(kafka);
```

This will eliminate the largest shared-state problem (Kafka topics) but requires more setup (network configuration, topic creation).
