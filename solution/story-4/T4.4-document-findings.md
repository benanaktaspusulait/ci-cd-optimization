## 1. Summary of Findings

| Finding | Detail |
|---------|--------|
| Testcontainers works locally | ✅ No barriers — Java 17, JUnit 5, Docker available |
| Testcontainers feasible in CI | ⚠️ Requires RepoSync MR (DOCKER_HOST + RYUK env vars) |
| Redis is the ideal first candidate | ✅ Fastest startup, highest isolation benefit, simplest setup |
| Test startup improved | ~2-4 min → ~3-25s (85-98% reduction for infrastructure tests) |
| Test isolation achieved | Fresh containers per test class — no shared state |
| Compose still needed | For aggregators (custom apps) and full end-to-end flows |
| Coexistence works | Both approaches can run side-by-side via Maven profiles |

## 2. Constraints

### Technical Constraints

| Constraint | Impact | Workaround |
|-----------|--------|-----------|
| Ryuk incompatible with Drone DIND | Cannot auto-clean containers in CI | `TESTCONTAINERS_RYUK_DISABLED=true`; pod termination handles cleanup. **Already applied in Artifactory pipeline.** |
| CI Maven step lacks `DOCKER_HOST` | Testcontainers can't reach Docker daemon in CI pipeline `mvn clean install` step | RepoSync MR to add env var to CI Maven step (already present in Artifactory Maven step) |
| Aggregators are custom apps | Can't use standard Testcontainers modules for them | Keep aggregators in compose; only infra services in TC |
| `localstack:0.12.18` is old | Limited AWS service support | Pin to same version for compatibility; upgrade later |
| Cucumber tests tightly coupled to compose | Can't easily migrate existing Cucumber steps | Write new TC-based tests; don't rewrite existing ones |

### Organisational Constraints

| Constraint | Impact | Route |
|-----------|--------|-------|
| CI enablement requires RepoSync change | Can't run TC tests in CI without ACP approval | Propose RepoSync MR after local validation |
| Team must learn Testcontainers | Initial onboarding effort | Provide examples, pairing, documentation |
| All adaptors share same pipeline | Change must work for all FDP repos | Design for generic usage (shared infra helper class) |

## 5. What Testcontainers Does NOT Solve

| Problem | Why TC doesn't help | Better solution |
|---------|--------------------|-----------------| 
| Aggregator testing | Custom apps, need real images + full startup | Keep in compose |
| End-to-end flow testing | Needs all services interacting | Keep in compose |
| Performance testing | TC adds container overhead | Dedicated perf environment |
| Production-like testing | TC uses local Docker, not K8s | Staging environment |
| Compose for local debugging | Kafdrop, Jaeger UI useful for devs | Keep compose for local dev |
